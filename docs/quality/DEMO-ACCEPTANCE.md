# 演示环境验收记录

- 更新时间：2026-07-30
- 前端：Netlify 或本地 Vite
- 后端：FastAPI
- 图像生成：OpenAI `gpt-image-2`
- 默认质量：`low`
- Prompt：`voice-to-appearance-v1.1`
- 风险规则：`RISK-V1.3`

## 1. 当前演示边界

本记录用于去标识化演示，不得录入真实患者身份信息，也不代表医疗诊断或治疗结果。

- 医生：创建病例与邀请码、启动会话、录入 Q1–Q8、确认视觉特征、发起 GPT Image 2 生图、审核、授权、调整、回退和下载；
- 患者：凭一次性邀请码进入当前会话，只能查看医生审核并授权的图像，可在每个会话内提交最多 3 次调整并可报告不适；
- 管理员：维护医生账户和风险规则，查看聚合统计、脱敏审计与归档恢复，不读取病例正文、Q1–Q8、患者调整原文或图像。

每个新邀请码兑换后都会创建新的会话，Q1–Q8、患者满意状态和 3 次调整额度重新开始。

## 2. 生图验收边界

演示环境的业务图片必须由 GPT Image 2 生成。真实生图要求后端配置：

```dotenv
MODEL_PROVIDER=openai
OPENAI_API_KEY=<server-side-secret>
MODEL_NAME=gpt-image-2
MODEL_QUALITY=low
```

API Key 只能存在于后端或生成 Worker。未配置有效密钥时，真实生图应失败并显示可恢复错误，不能以测试占位图片冒充 GPT Image 2 成功。

为控制费用，人工验收单轮最多生成 5 张，常规回归优先复用已有版本。自动化测试使用不产生真实费用的可控测试替身验证异常分支。

## 4. 人工演示检查

1. 确认后端、数据库、Redis、对象存储和生成 Worker 可访问；
2. 确认 Netlify 的 `VITE_API_BASE_URL` 指向当前后端；
3. 使用去标识化病例创建新邀请码；
4. 患者兑换后，医生确认知情同意并启动；
5. 医生录入该会话 Q1–Q8，确认视觉特征并在当前页面发起生成；
6. 患者页面进入“医生正在生成图像，请稍候”；
7. GPT Image 2 返回一张 1024×1024 PNG；
8. 图像通过结构和安全检查后进入医生审核；
9. 医生授权前患者不可见，授权后患者才看到图片；
10. 患者选择满意时医生端短暂提示“患者满意当前图片”；
11. 患者选择调整时，可提交简体、繁体或英文建议；
12. 医生可直接接受、选择性改写后重新映射，或填写理由拒绝；
13. 风险输入在患者提交和医生改写阶段都必须阻断；
14. 医生结束会话后，患者立即看到结束提示，点击“知道了”返回患者登录页；
15. 新建第二个邀请码并兑换后，确认调整额度恢复为 0/3，生成入口不沿用旧会话进度。

## 5. 安全检查

- 患者调整原文不直接发送给 GPT Image 2；
- 医生改写必须重新经过 `RISK-V1.3`；
- 简体、繁体和英文风险输入均能判定；
- 图片必须通过 PNG 结构检查和独立语义安全复检；
- 安全检查失败保留旧授权版本；
- 医生审核和会话授权缺一不可；
- 日志不包含 API Key、完整 Prompt、患者原文或风险命中原文。

## 6. 已知非生产限制

- Netlify 只托管静态前端；
- 后端若运行在个人电脑并使用临时隧道，待机、断网、进程退出或地址变化都会使登录和生图不可用；
- 正式试点仍需稳定后端域名、机构级密钥管理、监控、费用预算、邮件服务和运维方案；
- 移动端英文首页裁切尚待修复和复验。

GPT Image 2 的详细线上状态与复验要求见 `docs/quality/ONLINE-ACCEPTANCE.md`。
