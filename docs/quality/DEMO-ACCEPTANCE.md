## 1. 当前演示边界

本记录验证不依赖真实 OpenAI Key、邮件供应商和正式域名的业务闭环。演示环境不得录入真实患者身份信息，也不作为真实临床诊断或治疗系统使用。

三类角色保持如下边界：

- 医生：创建并管理自己的匿名病例、监督患者会话、录入 Q1–Q8、确认视觉特征、生成、审核、授权、回退和下载指定版本；
- 受邀患者：凭一次性邀请码进入当前监督会话，只能查看医生已审核且授权的 Avatar，最多提交三次调整建议并可安全暂停；
- 系统管理员：维护医生账户和风险规则，查看聚合统计、脱敏审计和归档恢复，不读取病例原文、Q1–Q8、患者调整原文或 Avatar 图片。

## 3. 演示前人工检查

每次正式演示前按顺序检查：

1. `docker compose ps` 中 API、数据库和 Redis 为健康状态，Worker、Scheduler、MinIO、前端为运行状态；
2. 打开首页、医生登录、患者邀请码和管理员登录页面；
3. 使用去标识化示例病例，不录入姓名、身份证号、联系方式或真实病历号；
4. 医生完成单题访谈、视觉确认、Mock 生成、医生审核和患者授权；
5. 患者端确认看不到 Q1–Q8、版本历史、下载按钮和模型内部信息；
6. 提交一条安全调整和一条风险调整，确认都不会由患者直接触发生图；
7. 管理员确认只能看到聚合数据和脱敏审计；
8. 演示结束后结束患者会话，避免旧页面继续访问。

### 可控失败演示

Mock Provider 支持通过根目录环境变量切换演示场景：

```dotenv
MOCK_IMAGE_SCENARIO=success
MOCK_IMAGE_DELAY_SECONDS=0
```

`MOCK_IMAGE_SCENARIO` 可选 `success`、`temporary_failure`、`moderation_blocked` 或 `invalid_image`。修改后重建 API 和 Worker，即可验证失败状态、旧版本保留与医生重试页面；完成异常演示后应恢复为 `success`。
