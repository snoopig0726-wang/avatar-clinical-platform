- 产品：幻听患者个性化 Avatar 生成系统
- 状态：Current

## 1. 跨文档处理原则

PRD、架构、API、数据、安全、Prompt、参考代码和测试材料均是重要输入，不设置固定的文档优先级。

出现差异时，结合以下因素选择更合理、全链路一致的方案：

1. 临床安全与患者隐私；
2. 产品目标和角色权限；
3. 技术可实现性、可恢复性和可审计性；
4. 自动化测试与验收证据要求。

无法合理兼容且会改变产品行为时，停止假设并请求产品方确认。

## 2. V1 角色边界

### 医生

医生是病例和 Avatar 的主要操作者，也是当前会话监督者。医生可以：

- 创建、查看和归档自己的病例；
- 创建、管理和撤销邀请码；
- 启动、恢复和结束受监督会话；
- 当面询问患者并录入 Q1-Q8；
- 查看、修改和确认视觉特征；
- 发起生成、同特征重新生成和修改特征后重新生成；
- 完成图片人工审核并授权当前版本；
- 查看全部版本、回退历史版本和下载指定已审核版本。

V1 不实现医生间共享、转交、多人审核或病例协作；病例创建医生兼任当前监督医生。

### 受邀患者

患者不创建账户，只进入当前一次性受监督会话。患者可以兑换邀请码、等待医生启动、查看已授权当前 Avatar、提交调整建议和触发安全暂停。

患者不能访问病例列表、Q1-Q8、历史版本、未审核图片、Prompt、模型信息或审计数据，也不能自主生成、重新生成、回退、授权、删除或下载 Avatar。

### 系统管理员

管理员可以审批或停用医生账户、维护风险规则、查看聚合统计和脱敏审计，并恢复未到删除期限的归档病例。

管理员不得查看病例原文、Q1-Q8、患者调整原文、有效视觉特征详情、Avatar 图片、Prompt 或模型请求内容。恢复操作只使用最小化病例元数据。

所有权限必须由后端执行，不能只依赖前端隐藏入口或按钮。

## 3. 首轮 Q1-Q8 与生图流程

首轮 Q1-Q8 不执行患者调整文本风险拦截，也不开发基于 Q1-Q8 的 `normal/sensitive/crisis/high_stimulus` 风险分级器。

正式流程为：

```text
医生当面询问并录入 Q1-Q8
  -> 字段、权限和状态校验
  -> 声音到视觉特征映射
  -> 医生检查、确认或进行受控覆盖
  -> 形成 effective_visual_features
  -> 使用统一 Prompt 模板构建供应商无关请求
  -> 图像生成
  -> 图片安全检查
  -> 医生人工审核
  -> 授权患者查看
```

如现有 Prompt Builder 的输入契约仍要求 `risk_level`，由后端内部兼容性地填充 `normal`，不得将其展示为对患者或幻听内容的风险判断。

首轮风险控制依靠固定低刺激 Prompt、安全禁止项、独立图片安全检查和医生人工审核。

## 4. 情绪字段

- `emotions` 只能使用六种固定枚举；
- 至少选择一项，最多选择六项；
- 不允许重复值、`other` 或自由文本情绪；
- 多情绪同时选择时必须执行柔和与中和规则。

参考代码中的 `max_length=6` 保持不变。其他文档中“最多三项”的表述按本决策统一为最多六项。

## 5. 风险拦截范围

风险控制分为两条独立链路：

1. 生成图片内容通过 `ImageSafetyAdapter` 检查，失败时不保存为可授权版本、不向患者展示；
2. 患者后续调整文本严格执行正式版 `AI-SAFETY.md`，通过后只创建待医生审核请求，患者原文不得直接进入图像模型。

## 6. 医生重新生成

医生拥有两种重新生成能力：

### 同特征重新生成

- 复用已经确认的 `effective_visual_features`；
- 不重新解释 Q1-Q8，也不重置医生覆盖；
- 生成新的候选版本。

### 修改后重新生成

- 医生修改 Q1-Q8 或允许编辑的视觉特征；
- 系统重新执行映射；
- 医生再次确认后生成新的候选版本。

两种模式均不消耗患者三次调整额度，不设固定产品次数上限，但同一病例同时只能存在一个活跃生成任务。每个新候选版本仍须经过图片安全检查、医生审核和重新授权。新版本授权前，患者只能看到原已授权版本。

## 7. 患者调整次数

- 每个病例在整个生命周期内最多创建三条风险校验通过的调整请求；
- 风险通过并成功创建调整请求时消耗一次额度；
- 医生拒绝、生成失败、取消或图片安全检查失败不返还额度；
- 风险拦截、风险服务异常、会话无效或未创建请求时不消耗额度；
- 新建患者会话不会重置病例调整额度；
- 同一病例同时只能有一条待审核、待确认或生成中的调整请求。

## 8. 30 天删除

- 只有病例归档才启动 30 天删除计时；
- 单纯结束患者会话不启动删除计时；
- 管理员恢复病例不暂停、不重置原删除期限；
- 恢复后的页面必须显示剩余保存时间；
- 到期时结束所有相关会话，并永久删除数据库业务数据、图片、版本、调整数据、风险数据、会话凭证、对象存储文件和备份；
- 删除失败必须保持失败或重试状态并告警，完成前不得标记成功。

## 9. 知情同意

医生启动受监督会话前必须确认已经完成现场知情同意。后端记录确认医生、确认时间和声明版本；V1 不要求患者在线签名或建立患者账户。

## 10. Prompt 留存边界

为满足生成追溯要求，最终发送给 Provider 的完整 Prompt 可以作为受限业务数据加密保存，并随病例到期删除。

完整 Prompt 不得进入普通日志、审计日志、前端响应、下载包或管理员界面。普通追踪只保存 Prompt 模板版本、内容哈希、Provider、模型版本和供应商请求 ID。

## 11. 首版 UI

- 首版页面结构和交互参考 PRD 中的原型图；
- 原型图不是最终视觉稿，后续允许整体调整；
- 前端首版仍要求精致、统一、低刺激、专业且可访问；
- 医生端强调操作效率，患者端强调简洁与安全感，管理员端强调权限边界；
- 使用可配置 Design Tokens 和复用组件，确保后续换肤和改版成本可控；
- 必须实现加载、空状态、错误、重试、禁用、等待、成功、会话过期和权限拒绝状态。

## 12. 协作与风险沟通

如果实现要求受到外部模型能力、供应商限制、技术成本或规范歧义影响，并会造成明显延期或产品降级，应及时说明阻碍、影响、备选方案和推荐方案，不得擅自降低关键需求。
